# 影视站点转 TVBox 源 指南

> 如何把一个影视网站变成 TVBox app 能加载的"源(site)"。配套 [ARCHITECTURE.md](./ARCHITECTURE.md) 的 §3/§4 阅读。

## 核心概念

TVBox 里的"源"本质是**一个能返回标准格式数据的接口**。app 不关心站点长什么样，只关心你能否提供这 5 类数据：

1. **分类**（有哪些频道/类型）
2. **首页/分类列表**（某个分类下的影片列表，支持分页）
3. **详情**（影片信息 + 剧集/播放线路）
4. **搜索**（按关键词返回影片列表）
5. **播放地址**（把某一集解析成可播放的真实 URL）

所谓"转源"，就是**在站点和这套标准接口之间搭一个适配器**。对应 `bean/SourceBean.type`，有 4 种方式。

---

## 方式对比总览

| 方式 | type | api 形式 | 开发量 | 适用场景 |
|------|------|----------|--------|----------|
| CMS/苹果 API | 0/1 | `.../provide/vod/` | 几乎为零 | 站点本身是 maccms 等 CMS 架构 |
| JS Spider | 3 | `xxx.js` | 中 | 站点只有网页，最主流做法 |
| Python Spider | 3 | `xxx.py` | 中 | 同上，偏好 Python |
| JAR Spider | 3 | `csp_Xxx` + `jar` | 高 | 复杂逻辑/高性能，需 Java |

> `type` 含义：0=XML 接口，1=JSON 接口，3=Spider(爬虫，含 jar/js/py)，4=扩展 HTTP API。
> 分发逻辑见 `ApiConfig.getCSP()`：api 以 `.js` 结尾走 JsLoader，含 `.py` 走 pyLoader，否则走 JarLoader。

---

## 方式一：CMS/苹果 API（type 0/1，最省事）

很多影视站用 **苹果 CMS（maccms）** 建站，自带标准采集 API，直接就能当源，**无需写代码**。

**判断**：访问 `站点域名/api.php/provide/vod/` 或 `.../provide/vod/?ac=list`，若返回规整 JSON/XML（含 `list`、`vod_name`、`vod_play_url` 等字段）即可用。

**配置**（写入配置 JSON 的 `sites` 数组）：

```json
{
  "key": "my_site",
  "name": "我的站",
  "type": 1,
  "api": "https://example.com/api.php/provide/vod/",
  "searchable": 1,
  "quickSearch": 1,
  "filterable": 1
}
```

**app 侧处理**：`SourceViewModel.getSearch()` 对 type 0/1 就是 `OkGo.get(api).params("wd", 关键词)`（type 1 额外带 `ac=detail`）。搜索/详情/播放都走这一个 api。

---

## 方式二：JS Spider（type 3，最常用）

站点只有网页、没有现成 API 时，写 JS 爬虫，跑在 `:quickjs` 引擎上。

**配置**：

```json
{
  "key": "my_js_site",
  "name": "我的JS站",
  "type": 3,
  "api": "https://your-host.com/spider/mysite.js",
  "ext": ""
}
```

**需实现的函数**（对应 `Spider.java` 方法）：

| JS 函数 | 作用 | 返回结构 |
|---------|------|----------|
| `init(cfg)` | 初始化 | - |
| `home(filter)` | 首页分类 | `{class:[{type_id,type_name}], filters:{}}` |
| `homeVod()` | 首页推荐 | `{list:[...]}` |
| `category(tid,pg,filter,ext)` | 分类列表页 | `{list:[{vod_id,vod_name,vod_pic,vod_remarks}], page, pagecount, limit, total}` |
| `detail(id)` | 详情+剧集 | `{list:[{vod_id,vod_name,vod_play_from,vod_play_url}]}` |
| `search(wd,quick)` | 搜索 | `{list:[...]}` |
| `play(flag,id,flags)` | 播放地址 | `{parse:0/1, url:"真实地址", header:{}}` |

**数据字段约定**（maccms 风格）：

- 列表项：`vod_id`（详情用的 id）、`vod_name`（名称）、`vod_pic`（封面）、`vod_remarks`（备注，如"更新至10集"）
- 详情项：`vod_play_from`（播放源名，多个用 `$$$` 分隔）、`vod_play_url`（剧集，格式 `第1集$url1#第2集$url2`，多线路用 `$$$` 分隔并与 `vod_play_from` 对应）

**JS↔Java 桥接工具**（`catvod/crawler/js/`）：JS 里可用 `req`/`Connect`（发 HTTP 请求）、`HtmlParser`/`pdfa`/`pdfh`（解析 HTML）、`Crypto`（加解密）、`Json` 等。

### JS Spider 骨架模板

```javascript
// mysite.js —— 套着改即可
var siteUrl = 'https://example.com';

var rule = {
  // 初始化，cfg 里含 ext 等
  init: function (cfg) {},

  // 首页分类
  home: function (filter) {
    return JSON.stringify({
      class: [
        { type_id: '1', type_name: '电影' },
        { type_id: '2', type_name: '电视剧' }
      ]
    });
  },

  // 分类列表页（抓列表页 HTML → 解析影片）
  category: function (tid, pg, filter, extend) {
    var url = siteUrl + '/type/' + tid + '/page/' + pg + '.html';
    var html = req(url, { method: 'get' }).content;
    var list = [];
    // 用 HtmlParser 解析出每个影片卡片，填充 vod_id/vod_name/vod_pic/vod_remarks
    // list.push({ vod_id: '...', vod_name: '...', vod_pic: '...', vod_remarks: '...' });
    return JSON.stringify({
      list: list, page: parseInt(pg), pagecount: 999, limit: 20, total: 99999
    });
  },

  // 详情 + 剧集
  detail: function (id) {
    var html = req(siteUrl + '/detail/' + id + '.html', { method: 'get' }).content;
    var vod = {
      vod_id: id,
      vod_name: '',           // 从 html 解析
      vod_pic: '',
      vod_content: '',
      vod_play_from: '线路1',  // 多线路用 $$$ 分隔
      vod_play_url: '第1集$playId1#第2集$playId2'  // 与 from 对应
    };
    return JSON.stringify({ list: [vod] });
  },

  // 搜索
  search: function (wd, quick) {
    var html = req(siteUrl + '/search?wd=' + encodeURIComponent(wd), { method: 'get' }).content;
    var list = [];
    // 解析搜索结果，同 category
    return JSON.stringify({ list: list });
  },

  // 播放地址（最关键）
  play: function (flag, id, flags) {
    // id 是 detail 里 vod_play_url 填的 playId
    // 解析出真实可播地址：
    var realUrl = /* 从播放页解析出的 m3u8/mp4 */ '';
    return JSON.stringify({
      parse: 0,               // 0=直链可播；1=交给 app 解析接口
      url: realUrl,
      header: { 'User-Agent': 'Mozilla/5.0', 'Referer': siteUrl }
    });
  }
};
```

## 方式三：Python Spider（type 3，`.py`）

思路同 JS Spider，用 Python 写，跑在 `:pyramid`（内嵌 Python）上，对应 `PythonSpider`。

```json
{ "key": "my_py", "name": "Py站", "type": 3, "api": "https://host/spider/mysite.py" }
```

需实现 `homeContent` / `homeVideoContent` / `categoryContent` / `detailContent` / `searchContent` / `playerContent`（同 Spider 契约）。适合偏好 Python 或需要 Python 库处理复杂加密的场景。

---

## 方式四：JAR Spider（type 3，`.jar`）

用 Java 写完整 Spider，继承本项目 `com.github.catvod.crawler.Spider` 基类，实现 `homeContent`/`categoryContent`/`detailContent`/`searchContent`/`playerContent`，编译成 jar。app 通过 `JarLoader` 用 `DexClassLoader` 动态加载 `com.github.catvod.spider.<类名>`。

```json
{ "key":"my_jar", "name":"Jar站", "type":3, "api":"csp_MySite", "jar":"https://host/spider.jar" }
```

开发/调试成本最高，适合复杂逻辑或高性能需求，一般站点用不到。

---

## 核心难点：搞定"播放地址"

不管哪种方式，最难的永远是 `play()`——从详情页拿到真实可播地址。站点常把地址加密/动态生成/加 referer 校验。三种拿法：

1. **直接解析真实链接** → 返回 `parse:0` + url + 必要 header（Referer/UA）。最理想。
2. **交给 app 解析接口**（VIP 解析）→ 返回 `parse:1`，app 用配置 `parses` 里的解析器去解（如爱优腾 VIP）。VIP flag 由 `ApiConfig.getVipParseFlags()` 标记。
3. **WebView 嗅探** → 让 app 打开播放页自动嗅探视频请求。对应 `Spider.isVideoFormat()` / `manualVideoCheck()` 与 `PlayFragment` 嗅探逻辑，可配合 `SourceBean.clickSelector` 指定需点击的元素。适合解析不出但网页能播的站点。

`play()` 返回后，`SourceViewModel.getPlay()` 与 `PlayFragment.doParse()` 负责后续：`parse:0` 直接播，`parse:1` 走解析器。

---

## 完整流程

```
1. 判断站点类型
   ├─ 有 maccms/CMS API？ → 方式一，直接填 api，几乎零开发 ✅
   └─ 只有网页？ → 写 Spider
        ├─ 会 JS → 方式二 JS Spider（最主流）
        ├─ 会 Python → 方式三
        └─ 要极致性能/复杂逻辑 → 方式四 JAR

2. 实现 5 类数据：分类 / 首页 / 分类列表 / 详情剧集 / 搜索
3. 重点攻克 play()：真实地址（直链 / VIP解析 / WebView嗅探）
4. 把 Spider 托管到可访问 URL（GitHub raw / 自己的服务器 / CDN）
5. 在配置 JSON 的 sites 数组加一条，指向你的 api / jar
6. app 加载该配置即可搜索/播放
```

## 现成的转源工具与生态（不想从零写时）

社区已有成熟的"规则驱动"框架和现成源仓库，可大幅降低门槛。以下为综合整理，非逐字引用，请自行核对最新状态与合规性。

### 规则驱动框架（填规则，不写完整爬虫）

- **drpy / dr_py**（"道长"系）：核心思路是**为每个站点填一份"规则"**（首页/分类/详情/搜索/播放各用什么 CSS 选择器或正则提取），框架把它转成标准源。
  - `dr_py`（Python 版）：自建 HTTP 服务托管规则，对外暴露成一个源地址填进 TVBox。参考备份仓 [jinjin327/dr_py](https://github.com/jinjin327/dr_py)。
  - `drpy2`（JS 版）：规则以 `.js` 运行，正好对应本项目 **JS Spider（type 3，`.js`）**，托管好 `.js` 直接填进 `sites`。
  - 与本项目关系：drpy 生成/运行的就是本文"方式二/三"，把"写爬虫"简化成"填规则模板"。
- **hipy / zyfun**（Hiram-Wong 系）：另一套 T4/JS 源的运行与调试生态，`hipy` 偏服务端，`zyfun` 为配套播放/调试端（社区有大量现成 JS 源分享，见 [zyfun discussions](https://github.com/Hiram-Wong/zyfun/discussions/180)）。定位与 drpy 类似，属"规则 + 运行时"路线。

### 免转：苹果 CMS 采集接口

若目标站点本身是 **maccms** 建站，它自带 `/api.php/provide/vod/` 标准接口，**无需转源**，直接当 type 0/1 源填入（即本文"方式一"）。大量资源站属于此类，最省事。

### 现成源/规则仓库（直接用或参照学习）

- [xuexuguang/tvbox_spider](https://github.com/xuexuguang/tvbox_spider) —— jar/js 自定义 spider 合集
- [mrgaoshuiquan/tvbox-config](https://github.com/mrgaoshuiquan/tvbox-config) —— 集成自定义 Spider 的配置仓
- FongMi 影视相关仓库（如 CandyMujForks 系）—— 大量现成源

### 如何选择

| 你的情况 | 推荐 |
|----------|------|
| 站点是 maccms 建站 | 免转，直接填 API（方式一） |
| 站点只有网页，想少写代码 | drpy2（JS 规则）或 hipy，填规则模板 |
| 想直接用现成的 | 抄上述源合集仓库里的 `.js`/`.jar` |
| 逻辑复杂/要高性能 | 自己写 JAR Spider（方式四） |

### 重要现实提醒

**没有任何工具能"输入网址、一键全自动出源"**。每个站点的 HTML 结构、分页方式、尤其是**播放地址的加密/防盗链**都不同，规则里的选择器和 `play` 解析逻辑仍需针对具体站点手动调。drpy/hipy 省掉的是"搭爬虫框架"的活，省不掉"分析这个站点"的活。此外，转源涉及第三方网站内容，请自行确认使用场景的合法合规与站点服务条款。

---

## 调试建议

- 先用浏览器/Postman 摸清站点的列表页、详情页、播放页的请求与返回，确定数据在 HTML 还是接口里。
- 单独验证 `search` 和 `play` 两个最关键函数。
- 播放失败时优先排查：真实地址是否需要 Referer/UA header、是否被防盗链、是否是需要二次解析的加密流。
- 可先接入一个已知能用的 CMS 源（方式一）验证 app 侧配置链路无误，再替换成自研 Spider。
